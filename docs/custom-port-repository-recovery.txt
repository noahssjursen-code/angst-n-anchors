Custom port recovery baseline
15 October 2026

When the primary JSON is missing or corrupt, save now compares against a valid
backup before replacing the primary. The same port/world, monotonic revision and
same-revision content rules apply to both sources. An unknown newer recovery
format also blocks replacement. Rejected writes preserve both files exactly.

This closes a reproduced rollback: a revision-3 backup held 1,250 kg aboard and
its load receipt, while an old revision-2 caller held neither. Saving that caller
used to return success and replace the recoverable document with the older one.
The same path could also be claimed by an entirely different port.

Explicitly saving the identical recovered state still repairs the primary. Raw
authored JSON recovery documents remain supported and their bytes are retained.
This is local document protection, not a multi-writer database transaction or
protection against a person intentionally editing their own files.

Focused regression: tests/custom_port_repository_recovery_test.tscn, launched
with --shipyard-playtest and a separate APPDATA profile. Covers missing,
truncated and checksum-invalid primaries, raw backups, stale/equal-revision
conflicts, foreign ID/world, preserved cargo receipts, repair and subsequent save.

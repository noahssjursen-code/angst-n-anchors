Cargo replication implementation — 2026-10-13

The captain collects existing ContainerUnit records and exact locations from
cargo pads and the operating crane. cargo.manifest.publish sends changes through
WorldGateway and the reliable remote command service. Commands carry an expected
revision and an idempotent receipt. Unknown transport outcomes retry the same
receipt; conflicts fetch the current revision before trying again.

The server checks durable vessel ownership, berth identity, duplicate container
IDs, finite transforms, supported container types and crane-operation ownership.
It stores the latest manifest and events in the existing authority store. Vessel
interest and port interest expose copies of the same version. Port observers can
see waiting containers before the vessel has assembled. Departure retires the old
port copy once all cargo is aboard.

Observers preserve container identity across quay -> hook -> vessel transitions.
Crane joints interpolate every rendered frame. Deck positions are vessel-local;
cargo follows the moving hull. Remote containers are excluded from local pickup
queries. The public projection contains contents, routes, values, paint, slot IDs
and transforms; remote hulls also expose their received cargo_manifest metadata.

cargo. Existing FreightService issuance and crane simulation still run on the

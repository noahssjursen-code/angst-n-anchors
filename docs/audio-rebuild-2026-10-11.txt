Approve or Deny. Add a note about what is wrong or what should be preserved.
Reset restores Unreviewed. Next unreviewed skips decided clips. The list marks
each decision and the header counts approved, denied and remaining clips.
Review decisions save automatically to user://audio_reviews/decisions.json,
separately from captain saves. Typing notes does not activate playback shortcuts.
Export report opens a save dialog for JSON. Its chosen path is copied after a
successful export. Send the file or paste the path into this chat. The report
includes every clip, verdict, notes, duration, loop flag and exact content hash.
Decisions are feedback only: denying a clip does not delete it during playback.

PRODUCTION RULES — project choices, not universal duration standards
------------------------------------------------------------------
1. Generate one identifiable source per clip. Keep water, wind, rain, engines,
   impacts and voices separate. Avoid composite storm ambience that duplicates
   those layers. No music, voices, cinematic booms or unrelated background noise
   in an isolated effect. Do not add real-world company identity or sound marks.
2. Continuous environmental textures: usually 12–30 seconds per take, preferably
   20–30 for exposed long listening. This library uses 12/14-second first takes
   and 24-second alternate weather takes. Crossfade between different takes over
   3.5 seconds after 40–120 seconds. A longer file alone does not prevent repetition:
   reject conspicuous rhythmic surges, calls or impacts baked into a bed.
3. Stable machinery: usually 5–12 seconds, 8 here for idle/load engines. Hydraulic
   and hoist motors use 5–6. Generate fixed operation at stable RPM/load; acceleration,
   startup and shutdown belong in separate sounds. Keep the same engine character
   across its states. Do not use idle/load pitch changes to invent physical RPM.
4. Clicks and footsteps: around 0.5–0.8 seconds generated, trimmed to the event.
   Door, rope and cargo actions: around 1–3 seconds. Start/stop: 2–3 seconds here;
   extend if the physical event needs it. Thunder: 6 seconds here, with complete
   decay. One-shot prompts request exactly one event, not a sequence or a loop.
5. Foghorns are single blasts with a runtime interval, not 30-second recordings
   containing silence. This harbour implementation schedules a blast every 30 s
   while local fog remains active. A held ship horn can use a stable sustain loop;
   that new clip is reserved until a horn input/event hook is implemented.
6. Request loop=true for every continuous generation. Review at least three joins.
   Reject fade-to-silence, changing timbre, baked impacts or repeated obvious events.
   Postprocessing removes DC, crossfades the boundary by 120 ms for engine/crane
   textures or 250 ms for other loops, and sets native forward looping in Godot.
   There is no end-of-file callback restart and no fade-to-zero at the wrap.
7. Keep untouched generated MP3s outside the game as source evidence. The API
   returned MP3; converting to WAV does not recover information lost to compression.
   Runtime assets are 44.1 kHz, 16-bit PCM WAV: mono for positioned effects and
   stereo for broad weather/thunder. Avoid a second lossy encoding stage here.
   Disable import normalization; it would undo the measured headroom. Longer
   future recordings may justify compressed streaming after measured memory review.
8. A sound effect should arrive immediately on its gameplay event, with its natural
   tail retained. Remove only leading/trailing near-silence; keep a tiny click-free
   edge fade on one-shots. Do not hard-cut engine starts using a guessed duration.
9. Leave mix headroom. This pass caps loop sample peaks at -4 dBFS and one-shot
   sample peaks at -6 dBFS; beds aim around -22 dBFS RMS and local machinery -20.
   Those are preparation targets, not an in-game loudness approval. Mix with the
   existing per-source gains and new Ambience/Machinery/SFX buses, all through
   Master. Review calm and maximum combined conditions before final level approval.
10. Frequent actions need independent takes: 3 each for steel/concrete steps,
    2 for several other footstep/contact sets. Do not select the previous take
    twice when another exists. Slight pitch variation can supplement, not replace,
    distinct recordings. Do not randomly change a running engine's identity.
11. Source position and distance must match the object. Footsteps/controls are
    close; cranes, water and engines have different hearing ranges; horns carry.
    Limit world one-shots to 32 active voices. Do not let an isolated preview's
    loudness dictate the final in-game mix.
12. Retain prompt, duration, loop intent, generation cost, SHA-256 and review state.
    Regenerate denied takes selectively. Never automatically spend the remainder
    of a budget. Reserve the expected cost before sending a request; stop on an
    uncertain outcome rather than blindly retrying a potentially billable request.

SYSTEM AUDIT
------------
Implemented in this pass:
- Native stream loops replace weather's finished-signal restarts.
- AudioLibrary centralizes manifest data, stream modes, buses and range profiles.
- One-shot/loop copies no longer mutate the same cached imported stream resource.
- Composite atmosphere stems were retired; sea/wind/rain remain independent.
- Roof rain now rotates alternate takes, as other weather layers do.
- Start fires on the existing inferred stopped/running transition, not every seat
  entry; removed the fixed 2.4-second start cutoff. Empty-fuel engines go silent.
- The close engine mix and positional engine layer use complementary gain rather
  than a fixed overlapping duck level. Existing simulation/propulsion is unchanged.
- Harbour foghorn uses a one-shot and timer, with existing fog hysteresis.
- Replaced the procedural watch beep with a generated library alarm.
- World one-shots have voice limiting, nonrepeating variants and category ranges.
- Showcase uses explicit manifest loop types rather than guessing from filenames.
- Per-file approval/denial, comments, persistence and portable report export.

Remaining design/integration work, explicitly not claimed complete:
- Engine running is still inferred from helm/throttle/autopilot and fuel. There
  is no authoritative independent ignition state; add one through the existing
  gameplay authority if true start/stop controls are desired.
- Foot contact currently dispatches steel aboard and concrete ashore. Wood,
  grating and gravel recordings are supplied but need real material tagging.
- Ship horn sustain is supplied but no horn input action currently exists.
- Fishing winch audibility currently follows trawling, rather than measured drum
  movement. Mooring uses motion-driven loops; direct rope-tension/contact-driven
  Foley would be more accurate when those events are exposed.
- Roof shelter is an overhead test, not full acoustic occlusion or room acoustics.
- Startup/shutdown retain the existing close one-shot implementation; full spatial
  ignition, NPC machinery mixing and multiplayer sound replication need dedicated
  ownership/event review. No multiplayer behavior was rebuilt in this pass.
- Listening approval, subjective engine identity, final loudness balance and the
  full-world stress mix remain review work. Waveform checks do not prove realism.

FULL GAME SOUND MAP
-------------------
Present gameplay / supplied replacement library:
Weather: calm/choppy/rough/storm sea, light/gale wind, drizzle/moderate/heavy rain,
roof rain and delayed thunder. Harbour: foghorn and local quay water.
Vessels: six engine banks x idle/load/start/stop, bow thruster, hull strain,
bow/stern wash, wave slap, helm controls, chair, lights and watch alarm.
Movement: steel/concrete/wood/grating/gravel steps, jump, landing, ladder/gangway
steps, water entry and wading. Doors: opening, closing and latch.
Mooring/boarding: line secure/release/strain, fender rubbing, gangway deploy/stow,
ferry ramp hydraulic movement and landing.
Cargo: crane slew/trolley/hoist/brake/grab, container lift/place, bulk pouring.
Fishing: gear deploy/retrieve, winch and net splash.

Potential additions (mapped, not fabricated as working systems or generated yet):
- Vessel interiors: ventilation, pumps, generator, interior machinery filtering,
  loose fitting rattle and occasional structural contact. Loop stable machinery;
  use sparse one-shots for rattle and impacts. Avoid a permanent haunted-ship creak.
- Vessel equipment: anchor windlass/chain/drop/contact, stern thruster variant,
  hatch/locker/cabinet/handrail interactions, bilge pump. Only wire to real equipment.
- Nautical alerts: autopilot disengagement, arrival, low fuel, engine fault,
  grounding/collision and departure interlock. Distinct restrained signals with
  priorities/cooldowns; do not continuously beep for the same acknowledged event.
- Ports: distant working cranes, forklift engine/reverse/brake, warehouse doors,
  loading conveyors and transfer pumps, road vehicles, crane warning bell.
  Use actual operating objects and distance, not a generic industrial noise wall.
- Coast and settlements: sparse gull calls, wind in rigging/trees, shoreline
  surf specific to shore type, occasional distant vessel horns, distant town tone.
  Wildlife calls must be events with suitable geography/time/density, not looped
  into every weather recording. Storm rain should not contain birds.
- Ferry service: passenger footsteps/luggage, boarding gate/door, ramp warning,
  departure chime, terminal PA chime and sparse nonverbal crowd texture. Speech
  and announcements require a separate voice/localization brief.
- Company/tablet/UI: quiet tap, navigation/back, accept/cancel/error, transaction
  confirmation, contract arrival and message notification. Event sounds need
  rate limits; no repeated hover sounds or arcade coin bursts for ordinary work.
- Economy/facilities: production machinery, hired crew activity, fueling and
  repair tools, fishing catch processing and bulk conveyor flows. Implement when
  corresponding authority/state exists, not by guessing from a scene label.
- Authoring editors: optional placement/erase/invalid-placement/undo feedback,
  a separate low-volume editor category; no gameplay machinery on every click.
- Human/NPC detail: clothing, hand contacts and breathing only where useful.
  Dialogue, languages, accessibility/subtitles and music are separate briefs.
